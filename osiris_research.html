1. Overview

OSIRIS is a production-grade, real-time OSINT dashboard positioned as an open-source alternative to Palantir. It aggregates live global intelligence feeds — flight tracking, maritime AIS, CCTV networks, earthquake monitoring, wildfire detection, conflict zone mapping, satellite orbits, and 24/7 live news streams — into a single GPU-accelerated map interface.

📦 Tech Stack

Next.js 16, MapLibre GL (WebGL), Tailwind CSS, Node.js 22 Alpine, Docker (~220 MB image)

🔓 License

MIT License — fully permissive for commercial use, modification, and redistribution

🚀 Deployment

Docker Compose, GHCR prebuilt images, CasaOS one-click install, keyless operation out of the box

2. Architecture

┌─────────────────────────────────────────────────────────┐ │ OSIRIS CLIENT (Next.js 16 + MapLibre GL + WebGL) │ │ ┌──────────────┐ ┌──────────────┐ ┌─────────────────┐ │ │ │ MapLibre GL │ │ HUD Panels │ │ RECON Toolkit │ │ │ │ GPU WebGL │ │ Layer Toggles │ │ Port Scan │ │ │ │ 60fps Render │ │ Entity Counts │ │ DNS / WHOIS │ │ │ │ │ │ Live Feeds │ │ SSL Inspector │ │ │ │ │ │ │ │ Vuln Scanner │ │ │ └──────────────┘ └──────────────┘ └─────────────────┘ │ ├─────────────────────────────────────────────────────────┤ │ NEXT.JS API ROUTES (proxy layer) │ │ /api/flights /api/earthquakes /api/cctv │ │ /api/news /api/fires /api/maritime │ │ /api/gdelt /api/satellites /api/weather │ │ /api/scanner /api/sentinel /api/osint/* │ ├─────────────────────────────────────────────────────────┤ │ EXTERNAL DATA SOURCES (public, mostly keyless) │ │ OpenSky · USGS · NASA FIRMS · NOAA · TfL · NVD │ │ GDACS · EONET · N2YO · aisstream.io · RSS Feeds │ └─────────────────────────────────────────────────────────┘

Key architectural decisions:

  • WebGL rendering, not DOM: All map markers, arcs, and heatmaps are rendered on the GPU via MapLibre GL. This enables 60fps with thousands of concurrent entities — critical for dense geospatial intelligence.
  • API route proxy pattern: Next.js server-side routes proxy external API calls, keeping API keys server-side and reducing client-side network overhead.
  • Viewport-aware loading: Data is fetched only for the visible map bounding box. Layers are lazy-loaded on toggle activation, not on page load.
  • Aggressive caching: A layerFetchedRef prevents duplicate API requests. Stable data sources poll at 15–30 minute intervals. Static data (news feeds) is served from memory with zero external calls.
  • Keyless by default: All core map layers work without any API keys. Optional keys (FIRMS, OpenSky OAuth2, N2YO, AIS) only increase rate limits.

5. Integration Paths for TirraMind

5.1 🗺️ Visualization Frontend for the GNN World Model

TirraMind's agent/models/world_model.py produces a heterogeneous graph with entities (vessels, companies, countries, infrastructure) and edges (trade flows, ownership, supply chain links). OSIRIS's MapLibre GL + WebGL architecture could render:

  • Entity nodes as interactive map pins with metadata popups
  • Edge relationships as geospatial arcs or flow lines
  • GNN attention weights as heatmap overlays or node color intensity
  • Embedding space clusters projected onto geographic coordinates
  • Conflict zones from political_risk.py using OSIRIS's severity-coded markers

Feasibility: OSIRIS is MIT-licensed. The MapLibre GL rendering layer can be adapted as a standalone React component library for TirraMind's inference API to serve.

5.3 🔧 RECON Toolkit → Infrastructure Monitoring Enrichment

TirraMind's existing infrastructure tools (dns_monitor.py, internet_outages.py, cert_transparency.py) monitor changes over time. OSIRIS's RECON toolkit adds point-in-time investigative capabilities:

  • Port scanner → detect live services on infrastructure nodes, feed into graph as SERVICE_RUNNING edges
  • SSL inspector → validate certificate chains for monitored domains, add CERT_EXPIRING risk edges
  • IP intelligence → enrich internet_infrastructure.py nodes with ASN, geolocation, and threat reputation
  • Vulnerability scanner → add CVE-based risk edges to infrastructure nodes in the world model

Note: RECON toolkit requires a separate scanner backend (SCANNER_URL/SCANNER_KEY). Without it, these tools return 503. This backend is not open-sourced in the OSIRIS repo.

5.5 🐳 Deployment Reference

OSIRIS's Docker patterns provide a reference for containerizing TirraMind's inference layer:

  • Multi-stage build: node:22-alpine → standalone Next.js output (~220 MB, non-root)
  • GHCR publishing: ghcr.io/aiacos/osiris:latest
  • Environment-driven config: All settings via .env file, no hardcoded values
  • CasaOS metadata: x-casaos: in docker-compose for one-click home-lab install

TirraMind could adopt a similar pattern: multi-stage Python Docker image → GHCR → env-driven config for the inference API.

6. Risks & Limitations

🟠 RECON Backend Not Open-Sourced

The scanner backend that powers the RECON toolkit (port scan, DNS, WHOIS, SSL, IP intel, vuln scan) is not included in the OSIRIS repository. Without SCANNER_URL/SCANNER_KEY, all RECON tools return 503. This means the cyber intelligence capabilities cannot be directly replicated — only the frontend UI patterns can be reused.

🟢 Frontend-Only Scope

OSIRIS is a dashboard, not an analytical engine. It visualizes data but does not model, predict, or infer. TirraMind's core value (GNN world model, Bayesian fusion, causal discovery) has no equivalent in OSIRIS. The value is in the visualization layer and data source discovery, not in analytical capability.

🟢 Tech Stack Mismatch

OSIRIS is JavaScript/TypeScript (Next.js). TirraMind is Python (PyTorch, PyG, NumPy). Any integration of OSIRIS's frontend would require either a polyglot deployment (Python API + Node.js frontend) or reimplementing the MapLibre GL patterns in a Python-compatible framework (Dash, Streamlit, or a custom FastAPI + Jinja2 + MapLibre GL JS setup).

🟠 Data Freshness Varies Widely

OSIRIS's data layers have inconsistent update frequencies: flights update every ~15s, but wildfires update every ~3 hours and conflict zones are manually curated. For TirraMind's real-time prediction use case, the slower layers may have limited value as live signals.
