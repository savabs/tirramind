# TirraMind Wiki Schema

This wiki is the compiled knowledge layer for TirraMind.

## Purpose

- Raw workflow artifacts remain the source material: `docs/research/`, `docs/specs/`, `tasks/active/`, `docs/memory/`, `README.md`.
- The wiki is the synthesis layer: topic-centric, cross-linked, persistent, and maintained by the LLM.
- `wiki/index.md` is content-oriented and generated by tooling.
- `wiki/log.md` is chronological and append-only.

## Invariants

- Do not modify raw source documents when updating the wiki.
- All wiki pages live under `wiki/pages/`.
- Every page must start with YAML frontmatter.
- Required frontmatter fields:
  - `title`
  - `type`
  - `summary`
  - `status`
  - `source_docs`
  - `updated_on`
- `source_docs` must be a YAML list of repo-relative source paths.
- Prefer path-based wiki links, for example `[[pages/architecture/system_overview]]`.
- Valuable query answers and synthesized comparisons should be filed back into the wiki as new pages rather than left only in chat.

## Page Types

- `architecture`: stable system structure and execution model
- `roadmap`: current phase state, sequencing, and open work
- `concept`: definitions and project ideas
- `entity`: durable named things such as modules, tools, or subsystems
- `analysis`: query outputs or focused syntheses

## Update Workflow

1. Read relevant raw sources.
2. Update or create wiki pages under `wiki/pages/`.
3. Maintain cross-links to adjacent pages.
4. Run `tirra-wiki-catalog` to rebuild `wiki/index.md` and surface lint findings.
5. Append a short entry to `wiki/log.md` for meaningful wiki changes.

## Page Creation Thresholds

Not every mention deserves its own page. Create a new wiki page when:
- A topic appears in **2+ research notes or specs** (cross-cutting concept).
- A topic is **central to a single source** and long enough that inlining would obscure the source doc.
- An entity (module, tool, subsystem) is referenced from **3+ other pages**.

If the threshold isn't met, add the info to an existing page's section or leave it in the source doc.

## Contradiction Handling

When sources disagree or a decision is revised:
1. **Note both positions** with dates: "As of YYYY-MM-DD, X was true. Superseded on YYYY-MM-DD by Y."
2. **Mark the page** with a `⚠️ CONFLICT` callout block at the top if the contradiction is unresolved.
3. **Add `contradicted: true`** to the page's frontmatter so lint can surface it.
4. **Do not silently overwrite** old information — the history of a decision is itself signal.

## Log Rotation

`wiki/log.md` is append-only and chronological. To keep it navigable:
- When `log.md` exceeds **500 entries**, rotate it:
  1. Move the current contents to `wiki/log-YYYY.md` (year of the last entry).
  2. Start a fresh `log.md` with frontmatter and a link to the archive: `Previous: [[log-YYYY]]`.
- Checkpoint files in `docs/memory/` follow a similar pattern — when there are more than **20 checkpoint files**, archive the oldest batch into `docs/memory/archive/` and add an index entry.

## Lint Expectations

Two lint tools cover different scopes:

### Wiki-only lint (`tirra-wiki-catalog`)
- No missing required frontmatter fields (title, type, summary, status, source_docs, updated_on).
- No duplicate page titles.
- No broken wiki links to missing pages within wiki/pages/.
- No orphan pages unless intentionally temporary.

### Vault-wide lint (`scripts/obsidian_lint.py`)
- **FM01** Missing frontmatter on non-exempt files.
- **FM02** Missing required fields (title, tags) in frontmatter.
- **FM03** Tags not in the known taxonomy (doc/, phase/, topic/, layer/, status/).
- **LK01** Broken `[[wiki links]]` — target file stem does not exist.
- **LK02** Orphan page — no incoming wiki links from any other file.
- **ST01** File exceeds line threshold (default 500).
- **ST02** Missing `## Related` section on research/spec/task files.
- **ST03** Stale file — not modified in git for >90 days.

Run vault-wide lint: `python scripts/obsidian_lint.py [--json] [--no-stale] [--threshold N]`

## Scope

This first slice is intentionally markdown-first and local-first. Dataview, Marp, Obsidian Web Clipper, and dedicated search tooling are optional extensions, not required dependencies.
