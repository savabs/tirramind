A.1 Market Microstructure & High-Frequency Trading

nkaz001/hftbacktest ⭐ ~2,500

MIT License Rust + Python HFT Backtesting

Production-grade HFT backtesting and market-making bot. Accounts for limit orders, queue positions, and latencies using full tick data (L2/L3 order books). Real-world crypto examples for Binance and Bybit. Written in Rust with Python bindings for speed. The most sophisticated open-source HFT backtester available.

🎯 TirraMind Take: If TirraMind ever moves into execution or market-making, this is the reference implementation. The queue position modeling and latency accounting are exactly what Jane Street-level firms use. For now, the order book data processing patterns are valuable for feature engineering — L2/L3 order book imbalance could be a graph node feature for short-term prediction signals.

LeonardoBerti00/LOBFrame ⭐ ~100

Python Limit Order Book

LOBFrame — open-source limit order book feature extraction. Extracts features from LOB data for market behavior analysis. Designed for ML-ready feature engineering from raw order book data.

🎯 TirraMind Take: Directly useful for adding order book features to TirraMind's graph. LOB features (spread, depth imbalance, order flow toxicity) could be node features for exchange/instrument nodes, providing microstructure-level signals that complement TirraMind's macro alternative data.

mjuchli/ctc-executioner ⭐ ~200

Python RL Execution

Limit order placement with Reinforcement Learning. Master's thesis project. Uses RL to optimally place limit orders on crypto exchanges. Addresses the two-step problem: (1) slice big orders optimally, (2) place child orders optimally in the order book.

🎯 TirraMind Take: The two-step decomposition (macro scheduling + micro placement) is a pattern TirraMind could adopt: GNN predicts macro-level price direction → RL agent handles micro-level execution. The RL state space design (order book state + inventory + time) is a good reference.

A.2 Options, Volatility & Pricing

XanderRobbins/Arbitrage-Free-Volatility-Surface ⭐ ~300

MIT License Python Volatility Surface

Production-grade arbitrage-free volatility surface toolkit. Computes implied volatilities (Newton-Raphson), enforces no-arbitrage constraints, fits SVI parametric models (Gatheral 2014), and calibrates Heston stochastic volatility models. Uses COS method (Fang & Oosterlee 2008) for efficient option pricing. Clean, well-documented, mathematically rigorous.

🎯 TirraMind Take: Options market data is a rich source of forward-looking information — the volatility surface encodes market expectations about future uncertainty. TirraMind could ingest vol surface parameters (SVI parameters, Heston params) as node features for instrument nodes. The no-arbitrage constraint enforcement is also valuable for data quality validation. This is the kind of sophisticated quant tooling that separates Jane Street from retail traders.

George-Dros/Volatility_Surface ⭐ ~100

Python / Streamlit IV Visualization

Interactive Streamlit volatility surface explorer. Visualizes skew patterns across maturities and strikes. Scenario testing for rate/dividend assumptions. Learning tool for understanding how option prices map to implied vol behavior.

🎯 TirraMind Take: The Streamlit visualization pattern is a good reference for TirraMind's own analytics dashboard. The vol surface skew metrics (butterfly, risk reversal) could be extracted as graph features — they encode market sentiment about tail risk.

A.3 Alpha Research & Factor Discovery

Morgansy/Genetic-Alpha ⭐ ~150

Python Genetic Programming

Genetic programming for alpha factor discovery. Evolves mathematical expressions (factors) from price/volume data using genetic algorithms. Automates the search for predictive alpha factors — the kind of work that quant researchers at Jane Street/Two Sigma do manually.

🎯 TirraMind Take: TirraMind's edge is in unique data, not formulaic factors. But genetic programming could be applied to TirraMind's alternative data — evolve factors from AIS vessel movements, satellite activity, or supply chain metrics. The genetic algorithm approach complements the GNN: GNN learns structure, GP discovers interpretable expressions. The combination is powerful.

parthmodi152/alpha-gpt ⭐ ~100

Python LLM + Alpha

LLM-guided alpha discovery with LangGraph. Uses GPT models to generate, evaluate, and iterate on alpha factors. Combines genetic programming with LLM reasoning for factor discovery. LangGraph orchestration for the research pipeline.

🎯 TirraMind Take: LLM-guided alpha discovery on TirraMind's alternative data is a compelling idea. An LLM could reason about "what factors might predict copper prices from maritime data?" and generate candidate features. The LangGraph orchestration pattern is reusable for TirraMind's research workflow automation.

changshun/Barra-Model ⭐ ~100

Python Barra Risk Model

Barra multi-factor risk model implementation. Style factor attribution, covariance estimation, risk decomposition. The industry-standard framework used by institutional quant funds for understanding portfolio risk.

🎯 TirraMind Take: Barra-style risk decomposition could be applied to TirraMind's predictions — attributing prediction uncertainty to specific factors (geopolitical, supply chain, weather, etc.). This provides explainability: "our copper prediction is 70% driven by maritime signals, 20% by satellite data, 10% by macro." Institutional investors demand this level of transparency.

A.4 Portfolio Optimization

PyPortfolio/PyPortfolioOpt ⭐ ~5,000

MIT License Python Portfolio Optimization

The definitive open-source portfolio optimization library. Mean-variance optimization, Black-Litterman allocation, Hierarchical Risk Parity (HRP), shrinkage estimators, and critical line algorithm. scikit-learn-inspired API. Production-ready.

🎯 TirraMind Take: When TirraMind produces multi-asset predictions, PyPortfolioOpt converts them into actual portfolio weights. The HRP method is particularly relevant — it uses hierarchical clustering on correlation matrices, which is structurally similar to how TirraMind's GNN clusters related entities. Black-Litterman allows incorporating TirraMind's predictions as "views" with confidence levels.

dcajasn/Riskfolio-Lib ⭐ ~3,500

Python Advanced Portfolio

Riskfolio-Lib — advanced portfolio optimization. Extends PyPortfolioOpt with Relaxed Risk Parity, Ordered Weighted Averaging (OWA), Black-Litterman with Augmented BL, constraints on tracking error and turnover. 10+ risk measures and 20+ objective functions.

🎯 TirraMind Take: The turnover constraint is critical for realistic trading — it prevents the optimizer from suggesting impractical daily rebalancing. The OWA approach allows blending multiple risk perspectives. Together with PyPortfolioOpt, this forms a complete institutional-grade portfolio construction layer for TirraMind's predictions.

A.6 Systemic Risk & Financial Networks

carloscinelli/NetworkRiskMeasures ⭐ ~100

R Network Risk

Risk measures for financial networks. Implements DebtRank, Impact Susceptibility, Impact Diffusion, and Impact Fluidity. Identifies systemically important institutions and simulates contagion scenarios. Used by central banks for financial stability monitoring.

🎯 TirraMind Take: TirraMind's graph is already a financial network — DebtRank could identify which entities (companies, countries, vessels) are systemically important. If a major shipping company shows distress, what's the contagion path through the supply chain? This is exactly the kind of analysis Palantir does for government clients. The R implementation would need porting to Python, but the algorithms are well-documented.

TommasoBelluzzo/SystemicRisk ⭐ ~200

MATLAB Systemic Risk

Comprehensive systemic risk framework. Implements CoVaR, Delta CoVaR, MES, SES, SRISK, and SCCA. Covers all major systemic risk measures from the academic literature (Adrian & Brunnermeier, Acharya et al., Brownlees & Engle).

🎯 TirraMind Take: The SRISK measure (capital shortfall in a crisis) is particularly relevant — it estimates how much capital an institution would need in a systemic event. TirraMind could compute SRISK-like measures for supply chain entities: "how much inventory buffer would Company X need if Port Y closes?" The MATLAB code provides reference implementations to port to Python.

Copula-based approaches could model tail dependence between TirraMind's alternative data signals.

B.1 Entity Resolution & Record Linkage

moj-analytical-services/splink ⭐ ~1,500

MIT License Python Entity Resolution

Fast, accurate, scalable probabilistic record linkage. Based on the Fellegi-Sunter model. Supports multiple SQL backends (DuckDB, Spark, Athena, PostgreSQL). Used by UK government (MOJ) for linking records at national scale. The leading open-source entity resolution library. 136 releases — actively maintained.

🎯 TirraMind Take: This is the missing piece for TirraMind's entity resolution layer. TirraMind ingests data from 51+ sources — companies appear under different names in SEC filings, AIS data, sanctions lists, and supply chain databases. Splink can probabilistically link these records into unified entity nodes. The Fellegi-Sunter model provides confidence scores for each link, which can become edge weights in TirraMind's graph. This is exactly what Palantir's entity resolution does — but open-source and Python-native.

OlivierBinette/Awesome-Entity-Resolution ⭐ ~500

Curated List Entity Resolution

Comprehensive entity resolution resource list. Covers libraries (Splink, Dedupe, Senzing), commercial tools (Quantexa, Reltio), cloud services (Google Enterprise Knowledge Graph), and research papers. The definitive map of the ER landscape.

🎯 TirraMind Take: Quantexa is particularly notable — it's a commercial entity resolution + graph analytics platform used by top-tier banks for AML and fraud. It validates that entity resolution + graph analytics is a proven high-value combination. TirraMind is building the open-source, prediction-focused version of this.

DerwenAI/ERKG ⭐ ~50

Python / Neo4j Entity-Resolved KG

Entity-Resolved Knowledge Graph tutorial. Demonstrates integration of Senzing entity resolution with Neo4j graph database. Hands-on Python tutorial with interactive visualization. Shows the full pipeline: raw data → entity resolution → knowledge graph → visualization.

🎯 TirraMind Take: The Senzing + Neo4j pattern is the open-source equivalent of Palantir's core pipeline. TirraMind could adopt: Splink (entity resolution) → PyG HeteroData (graph) → GNN (prediction) → MapLibre GL (visualization). This is a complete open-source Palantir + Jane Street stack.

B.4 Trade Surveillance & Market Manipulation Detection

Python / Java Trade Surveillance

Real-time market surveillance system. Monitors trading via ActiveMQ message queues. Detects flash crashes, spoofing, wash trading, and anomalous patterns. Uses Enterprise Integration Patterns (EIPs). Production-style architecture with message routing, validation, and anomaly detection pipelines.

🎯 TirraMind Take: The surveillance pattern (consume messages → validate → detect anomalies → alert) is directly applicable to TirraMind's data quality monitoring. The specific manipulation detection algorithms (spoofing, wash trading) could be adapted to detect anomalous patterns in alternative data feeds.

🎯 The Moat: Nobody Has This Full Stack

After surveying 50+ repos across two surveys, the conclusion is unambiguous:

  • Quant funds (Jane Street, Two Sigma) have the quant stack but rely on traditional data + price/volume signals. They don't fuse 51+ alternative data sources in a heterogeneous GNN.
  • Surveillance firms (Palantir, Quantexa) have entity resolution + graph analytics but don't do predictive GNN modeling or causal discovery.
  • OSINT platforms (OSIRIS, PANO) have visualization + data aggregation but no ML prediction layer.
  • Academic projects (THGNN, Neural-GC) have individual ML methods but on narrow, homogeneous datasets.

TirraMind is the only project that spans the full stack: alternative data ingestion → entity resolution → heterogeneous temporal GNN → causal discovery → Bayesian fusion → portfolio optimization → surveillance → visualization.

This is not a collection of features. This is a category-defining architecture. Build it.
