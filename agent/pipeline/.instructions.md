# Pipeline Module Conventions

## Architecture
This is the **deterministic execution engine**. No LLM calls, no randomness beyond retry jitter. SQLite for state, APScheduler for cron triggers, ThreadPoolExecutor for parallel node execution.

## Key Classes
- `PipelineStore` — SQLite persistence (WAL mode, dag_runs/pipeline_data/signals tables)
- `DAG` / `Node` — immutable DAG definition with cycle detection (Kahn's algorithm)
- `DAGExecutor` — parallel execution engine with retry, timeout, upstream injection
- `PipelineScheduler` — cron trigger wrapper (APScheduler)
- `DAGRegistry` — CRUD for named DAGs, `load_defaults()` from `dags/`
- `Operator` (ABC) — `ToolOperator`, `FunctionOperator` for node execution

## Conventions
- `from __future__ import annotations` at top of every file.
- Frozen dataclasses for configuration. Mutable state only in Store.
- All database operations use context managers (`with conn:` for transactions).
- New DAG definitions go in `agent/pipeline/dags/<name>.py` and register via `load_defaults()`.
- Operators wrap tools or pure functions — they never do both.
- Node names are snake_case, descriptive: `fetch_cftc`, `compute_ofi`, not `node_1`.

## Error Handling
- Operators catch all exceptions and return failure status — never crash the executor.
- Retry with exponential backoff (configurable per-node).
- Upstream failures cascade: downstream nodes are marked `skipped`, not `failed`.

## Testing
- In-memory SQLite (`:memory:`) for fast unit tests.
- `tmp_path` for persistence tests.
- Test files: `tests/test_pipeline_*.py`.

## Layer Rule
This is **Pipeline Layer**: deterministic, scheduled, parallel. Shares tools with Agent Layer but makes no LLM calls and has no exploration behavior.
