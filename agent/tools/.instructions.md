# Tools Module Conventions

## Tool Implementation Pattern
- Inherit from `Tool` (in `agent/tools/base.py`).
- Define class attributes: `name`, `description`, `parameters` (JSON Schema dict).
- Implement `async execute(**kwargs) -> ToolResult`.
- Return `ToolResult(success=True/False, output="human-readable", data={...})`.

## Code Structure
- `from __future__ import annotations` at top.
- Three-tier imports: stdlib → third-party → local (`from .base import Tool, ToolResult`).
- Module docstring: state the data source, URL, and any rate limits.
- Use `logging.getLogger(__name__)` for all logging.
- Use `DataCache` from `agent/data/cache.py` for HTTP response caching (SHA256 keys, 6hr TTL).

## Data Source Rules
- **Free APIs only.** No paid data sources unless edge has been proven on backtests.
- Document the source URL, rate limits, and data lag (T0, T1, T3, etc.) in the module docstring.
- Handle HTTP errors gracefully: return `ToolResult(success=False, output="error description")`.
- Set reasonable timeouts (30s default).
- Never expose API keys in output or logs.

## Research Discipline
- For new tools, unfamiliar APIs, or externally inspired fetchers, search GitHub for relevant OSS repositories and read authoritative documentation before implementation.
- Use multiple keyword variants and record repositories, docs, and reuse constraints in the feature research note.
- If a repository is not clearly compatible with commercial use, extract only the concept into the research note and implement the tool independently in TirraMind style.
- Start the research note from `docs/research/RESEARCH_TEMPLATE.md` unless a more specific structure is needed.

## Input Validation
- Validate all parameters at the `execute()` boundary using the JSON Schema in `parameters`.
- Reject unexpected types early. Return a clear error ToolResult, don't raise exceptions.

## Testing Requirements
- Every tool has `tests/test_<tool_name>_edge.py`.
- Mock all HTTP calls (use `unittest.mock.patch` or `responses` library).
- Test: missing required params, invalid param types, HTTP 4xx/5xx, timeout, empty response, malformed JSON.

## Layer Rule
This is **Layer 1: Surveillance Surface**. Fetch and normalize data. No math, no LLM calls. Raw data in, structured data out.
