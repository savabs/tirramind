2. What V61 Fixes

Problem 1: Embedding Collapse (48.4% in V60)

Solution: ContraNorm
Architectural anti-collapse layer applied after each HGT message-passing step. Prevents embeddings from collapsing into a narrow cone (dimensional collapse) by implicitly adding a contrastive uniformity pressure.
  • Zero parameters (no extra overhead)
  • Proven effective in PKU research (2023)
  • Complements VICReg (architecture + loss-based approach)
Expected: Collapse fraction drops from 48.4% to <20%, effective rank increases from 3.0/93 to >20/93.

Problem 2: Loss Scale Imbalance (value: 1653 vs return: 210)

Solution: Log Loss Transform + Reduced Weights
Applies log(L + 1) transformation to all task losses before combining, bringing them to comparable scales.
  • Prevents large-scale losses (value, obs_type) from dominating gradients
  • Allows small-scale losses (return) to contribute effectively
  • State-of-the-art from Dual-Balancing MTL (HKUST 2026)
Additionally:
  • value_weight reduced from 1.0 to 0.1 (value loss was 8× larger than return)
  • obs_type_weight reduced from 1.0 to 0.5 to prevent silencing other tasks
Expected: Return loss shows learning curve (not flat), all losses within same order of magnitude.

Problem 3: Flat Return Loss After Epoch 1

Solution: Combined Effect
The log loss transform + reduced value_weight should allow the return loss to receive sufficient gradient flow, enabling it to learn across all epochs instead of being silenced after epoch 1.

Expected: Return loss decreases over epochs, PurgedRanker IC turns positive (target: >+0.03, approaching V52's +0.047).
