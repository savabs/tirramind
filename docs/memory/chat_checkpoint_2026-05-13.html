1. Mission & doctrine

TirraMind is a predictive AI company, not a quant fund. The mission is to build the most capable real-world prediction system ever constructed — a living intelligence that watches physical reality (Layer 0: ships, weather, factories, grid, disease), behaviour (Layer 1: policy, trades, filings, social), and information flows simultaneously across every country, and outputs probability distributions over what happens next.

The edge is not data scale and not model size. The edge is the combination: unconventional observation × SOTA math × living-system architecture. Specifically, the math stack combines temporal heterogeneous GNNs, Bayesian belief propagation, Kalman signal fusion, RL policy under partial observability, EWC continuous learning, causal chain detection, and investigative entity linking — all running over 51 free-tier data sources nobody else looks at together.

The POMDP doctrine

The global system is treated as a Partially Observable Markov Decision Process: hidden states (actors act on private information), non-stationary environment (regimes shift), millions of latent intentions, sparse and delayed rewards. Every layer is designed to serve this structure:

  • GNN perceives the partially observable state from heterogeneous evidence.
  • World model represents uncertainty over hidden states (Bayesian DAG today; transformer-based world model is the Phase 48 target).
  • Kalman fusion is the belief-state estimator — combines noisy multi-source observations.
  • RL policy (SAC today, Dreamer-style model-based tomorrow) plans under that uncertainty.

Cost discipline

$0 spend until proven edge. All data is free-tier (SEC EDGAR, GDELT, CFTC, Polymarket, ClinicalTrials, ADS-B via OpenSky, ISO grids, FRED, Yahoo). All math is open source (pgmpy, pymc, filterpy, cvxpy, scipy, hmmlearn, statsmodels). LLM is Groq free tier / Claude Haiku for routing only. Compute is local-first with Kaggle as the GPU plane. The cheapest data is often the most valuable because nobody else is looking at it.

Model agnosticism doctrine (standing rule)

No model, method, or architecture is sacred. The current stack — pgmpy DAG, SAC RL, HetTGN GNN, Kalman fusion — is the best-justified choice right now for the data volume. After Phase 40 produces real backtests, any component not producing genuine predictive edge (measured by out-of-sample calibration, Sharpe attribution, or convergence signal quality) gets replaced or upgraded regardless of how much code was written for it. Sunk cost is not a reason to keep a weak model.

The GNN — TirraMind's central nervous system

The heart of the system is a Heterogeneous Temporal Graph Neural Network (HetTGN) living in agent/models/gnn/. It is the join layer that fuses 51 data sources into a single learned representation per entity per time.

  • Architecture: hidden_dim=128, 2 layers, 2 attention heads, ~1.96M params.
  • Heads: obs_type classifier (CE), value_head, return_pred_head (Phase 41 MLP 128→64→1), contrastive head, time_delta head.
  • Loss: multi-task weighted sum; Phase 49 added per-entity-type alignment weights from world-model likelihood gradient.
  • Memory: HeteroMemory GRU per node (entity state evolves continuously between training runs).
  • Continual learning: Elastic Weight Consolidation (EWC) with λ=1000, Fisher diagonal, sidecar ewc_state.pt persisted across subprocess boundaries — see Phase 46.

Data Acquisition Graph (DAG)

The DAG in agent/pipeline/dags/daily_collection.py defines the daily ingestion run. As of Phase 45.2 it has 29 nodes / 29 unique operators. 22 tools remain unwired and the next wave of DAG expansion is gated by GNN attention diagnostics (Signal Depth Doctrine — don't wire a 4th channel to an already-dense entity type; wire the missing link between disconnected clusters).

The Signal Depth Doctrine

Every data tool must be evaluated against three depth layers:

  • L1 (Aggregate): top-line numbers — commodity infrastructure.
  • L2 (Entity-level): resolve to individual filers, vessels, wallets, contracts. This is where alpha starts.
  • L3 (Cross-entity combinations): link entities across tools. The investigative-journalist test: "would a reporter find this output useful for uncovering something hidden?" If no, the tool is not deep enough.

5. The training loop, deconstructed

This is the part of the system that has caused the most pain and that the successor agent will spend the most time staring at. Read this carefully.

Block-structured training

Kaggle kernels have a 9-hour wall-clock limit. The full training loop is therefore broken into blocks of 5 epochs, with each block running in its own subprocess. The orchestrator is pipeline_orchestrator.py. It runs: 

while epochs_done < target_epochs and budget_left:
    subprocess(retrain_gnn.py --block-size 5)   # train 5 epochs
    subprocess(auto_improve.py)                  # detect pattern, write next_config.json
    epochs_done += 5

Why subprocesses (and why this caused bugs)

Each block runs as a separate Python subprocess so OOM or crashes don't kill the orchestrator. This means nothing in process memory survives between blocks — only what's persisted to disk. This bit us hard with EWC: the first implementation kept Fisher diagonal in memory and the EWC penalty effectively reset to zero every 5 epochs, producing obs_type loss spikes at every block boundary. The fix (commit 5ba8b2c) was to write Fisher and snapshot weights to ewc_state.pt after each block and reload them at the start of the next.

auto_improve.py — the adaptation brain

Between training blocks, scripts/auto_improve.py reads metrics.jsonl, classifies the recent training trajectory into a pattern, and writes next_config.json which the next subprocess reads. Patterns include: diverging, stagnating, improving, return_head_frozen, and (as of this session) improving_ic_positive and ic_degrading.

There is also an LLM advisor (Claude Haiku) that runs alongside the heuristic classifier — see commits bf789e4, 4b52bd0. The LLM proposes config changes; the heuristic is the safety net. The LLM never makes decisions unilaterally — it's L7 support.

The IC-gated triggers (added this session)

Before this session, auto_improve.py only looked at training loss. That's dangerous: a model can have stagnant or even rising training loss while producing positive predictive IC (the signal has just become harder to fit by self-supervision). Conversely, a model can have beautifully decreasing training loss while producing negative IC (memorising patterns that anti-correlate with future returns — exactly what Phase 41 found).

The new logic:

  • _load_ic_results(checkpoint_dir) reads ic_results.json written by the backtest. Returns the best strategy's mean Spearman IC, or None if no backtest has run yet.
  • New pattern improving_ic_positive: if IC > 0.02, return immediately with no config change — trust the predictive signal even if training loss is flat.
  • New pattern ic_degrading: if IC < −0.01, halve gdelt_frac and log the worst entity type from entity_type_losses. Limited to 2 consecutive triggers to prevent oscillation.
  • Graceful degradation: when no ic_results.json exists, all IC checks return None and the classifier falls back to pure loss-based heuristics.

The per-entity-type loss (added this session)

Every epoch now writes entity_type_losses and entity_type_counts dictionaries to metrics.jsonl. This is how ic_degrading identifies which entity type to throttle. Before this change the trainer aggregated obs_type CE into a single scalar; now both alignment-weighted and non-weighted branches use reduction="none" and per-ntype CE is accumulated.

The backtest CLI (added this session)

Before: scripts/phase40_gnn_backtest.py hard-coded MODEL_PATH and DB_PATH. To evaluate a different checkpoint you had to edit the source file. Now: --model-path, --db-path, --out argparse flags. The script also writes ic_results.json next to the model in the format {"model_path": ..., "strategies": {...}, "best": {"strategy": ..., "mean_ic": ...}}. This is the file that auto_improve._load_ic_results reads. The two systems are designed to talk to each other.

6. Kaggle workflow & gotchas

The canonical Kaggle reference is docs/memory/kaggle_runbook.md. Read it before touching anything on Kaggle. This section is the summary.

The two-dataset model

  • tirramind-code dataset — contains tirramind_code.zip and tirramind_code_p47.zip. Both zips must be kept in sync. Kaggle falls back to tirramind_code_p47.zip when git clone fails (which happens when the tirramind_token secret fails) — this is why V11–V14 crashed: only one zip had been updated.
  • tirramind-data dataset — contains pipeline.db and checkpoints/epoch_NNN.pt files. Checkpoint format is FLAT (checkpoints/epoch_NNN.pt, NOT checkpoints/h_g/epoch_NNN.pt). The zip command must preserve the subfolder — never zip -j.

Code source priority

  1. Kaggle first tries git clone git@github.com:savabs/tirramind.git using the tirramind_token secret.
  2. If git clone succeeds → code is fresh from GitHub main branch.
  3. If git clone fails (secret service flake) → falls back to tirramind-code dataset zip.
This is why the tirramind_v1/ sandbox bit us. The Copilot agent in the prior session edited files inside tirramind_v1/, which is an untracked subdirectory. Those changes never reached Kaggle. All canonical code is at root-level (agent/, scripts/) and tracked by git. Before editing any code that needs to run on Kaggle, verify you're editing the root-level file. The path test: git ls-files | grep <your-file> must return a result.

The Unicode replacement tool bug

Halfway through reapplying changes, the VS Code replace_string_in_file tool started failing silently. The cause: the trainer code contains box-drawing characters (─, U+2500) in comment lines. The tool's string-matcher fails on strings containing these. Workaround: for files containing box-drawing characters, drive replacements through a Python one-liner: open(file).read() → str.replace(old, new) → open(file, 'w').write(). This produced three Python patch scripts during the session that all completed cleanly.

  6. Wait ≥3 minutes after a Kaggle dataset upload before pushing a kernel. Dataset processing is eventually consistent.
  7. EWC state must persist across subprocesses. The block-structured trainer runs each block as a fresh Python process. Anything in process memory dies. Use ewc_state.pt sidecar.
  8. The LLM is never a decision-maker. It explains, parses, narrates. Numerical decisions are owned by the math layer. The Haiku advisor in auto_improve.py proposes; the heuristic classifier disposes.
  9. IC has priority over training loss. Phase 41 proved this empirically: training loss can decrease while IC goes negative. The new improving_ic_positive pattern (this session) codifies it.
  10. GDELT dominated the dataset at 91.3%. After the Goldstein filter (Phase 41b) the share drops to ~50%. Watch this number — auto_improve's ic_degrading trigger will halve gdelt_frac further if needed.
  11. Checkpoint format is FLAT on Kaggle: checkpoints/epoch_NNN.pt, not checkpoints/h_g/epoch_NNN.pt.
  12. Single-owner rule: each fact lives in exactly one file. memories/repo/tirramind_structure.md owns metrics. tasks/active/quant_training_ground.md owns the roadmap. Checkpoints are append-only history. Never edit a past checkpoint — record corrections in the next one.
  13. Write-gate protocol: a decision is not real until it's in a file. Write the canonical file in the same turn as the approval, then confirm.
  14. Workflow preflight is mandatory. Non-trivial work requires research + spec + active task file before any code is touched. Trivial = single-file, low-risk, no interface change.
  15. Vibe Coding Protocol: AI-owned work targets leaf nodes (low blast radius). Before each execution, spend 15–20 min jointly exploring the codebase with the model, then compress to one structured prompt. For leaf code: 1 happy-path test + 2 failure-case tests. Save exhaustive testing for non-leaf code.
