# Feature: Entity Linking Layer

## Goal

Add `link_entities()` calls to the existing L2 tools so the GNN has edges between entities, not just isolated nodes. This is the single highest-leverage infrastructure change identified by the Phase 16 diagnostic analysis.

**Problem:** All 12 L2 tools persist entities and observations but none create entity-to-entity links. The GNN's heterogeneous message-passing degrades to per-type autoencoders without edges. The entire value of Phases 12–16 (HetTGN, pattern recovery, fine-tuning, diagnostics) depends on connected entity neighborhoods.

**Evidence:** Phase 16c gap analysis ([[tool_priority_ranking]]) confirmed zero entity links in the graph. Synthetic diagnostic showed `port_call_to` and `exchange_based_in` edge types receive zero attention because they only exist in the synthetic generator.

## Search Log

- No external search needed — this is purely an internal wiring task using the existing PipelineStore link API (`link_entities()`) and existing entity data from L2 tools.

## Current Architecture

### PipelineStore link API (already implemented)

```python
store.link_entities(
    entity_id_a: str,   # source entity ID
    entity_id_b: str,   # target entity ID
    link_type: str,      # e.g. "works_for", "headquartered_in"
    source: str,         # tool name that produced the link
    confidence: float = 1.0,
    metadata: dict | None = None,
)
```

- Idempotent via `INSERT OR IGNORE` on `(entity_id_a, entity_id_b, link_type)`.
- Raises `ValueError` for self-links.
- Entity IDs are generated by `entity_id_from_key(entity_type, key)` and stored as deterministic SHA-256 prefixes.

### Guardrail: Hard-code facts, not intelligence

This phase is allowed to hard-code only **explicit factual relationships already present in the raw source data**.

Allowed:
- Person → company links stated by SEC filings
- Wallet → wallet links stated by blockchain transaction inputs/outputs
- Country → country links stated by bilateral event records
- Vessel → country links stated by destination/port metadata

Not allowed:
- Hand-coded predictive scores
- Hand-coded edge weights that imply market direction
- Hand-coded rules like "if link type X then bullish"
- Hand-coded latent relations that are not explicit in the source data

The learned part remains in the GNN and downstream pattern modules: embeddings, attention, edge-type usefulness, temporal motifs, crystallized patterns, and supervised fine-tuning.

### Graph builder consumption (already implemented)

`GraphBuilder.build()` calls `store.query_all_entity_links()` → `_build_edge_data()` → groups links by `(src_type, link_type, dst_type)` → creates `HeteroData` edge_index tensors. **No code changes needed in graph_builder.py.**

### L2 tool pattern

All L2 tools follow:
```python
def _persist_entities_inner(self, records):
    with PipelineStore(self._pipeline.db_path) as store:
        for record in records:
            entity_id = store.register_entity(type, name, ...)
            store.store_entity_observation(entity_id, obs_type, ...)
            # ← link_entities() calls go HERE
```

| Tool | Assessment |
|------|-----------|
| **dns_monitor** | Could link domain→company via WHOIS but data not in current fetch. Cloud provider field is a string, not an entity. **Skip for now.** |
| **wikipedia_pageviews** | Topic entities are standalone. Could link topic→company if article name matches a company, but this is fuzzy matching, not structural data. **Skip for now.** |
| **defi_flows** | Protocol entities could link to a blockchain/chain entity, but "chain" is not a current entity type. **Skip for now.** |

## Implementation Plan

### Batch 1: Tier A — person↔company links (insider_filings, form144)
Lowest risk: both entities already exist in the same persistence call. Just add one `link_entities()` call after the two entity registrations.

### Batch 2: Tier B.1 — intra-tool links (gdelt country↔country, whale_alert wallet↔wallet)
Both entities already persisted within the same tool. Add link call between them.

### Batch 3: Tier B.2 — cross-entity links requiring new entity creation (ais_vessel vessel→country, lobbying company→company, cert_transparency domain→company)
May need to `store_entity()` for the second entity before linking.

### Batch 4: Tier C — simple fixed-country links (interconnection_queue, patent_filings)
Country entity "US" needs to be created once, then link.

## Risks

- **Entity ID format consistency:** All tools must use the same ID format for the same entity. E.g., if insider_filings stores company as `"company:AAPL"` and lobbying stores it as `"company:Apple Inc."`, they won't link. Need to audit entity ID formats per tool.
- **Missing counterpart entities:** Some links (ais_vessel→country) require creating entities that don't currently exist. The `register_entity()` call is idempotent so this is safe.
- **Confidence calibration:** Links from structured identifiers (CIK numbers) get 1.0. Links from text matching (cert org field) get lower confidence.
- **Performance:** `link_entities()` is `INSERT OR IGNORE`, so idempotent and fast. No bulk-insert needed.
- **Scope drift risk:** This phase must not sneak in learned behavior as rules. Only explicit edge extraction is in scope.

## Observations

- **8 out of 12 tools** can produce meaningful entity links from data they already have.
- **3 tools** (dns_monitor, wikipedia_pageviews, defi_flows) don't have natural cross-entity data — skip for now.
- **1 tool** (whale_alert) links within same entity type (wallet→wallet) which is structurally valuable for the GNN.
- The graph builder already handles arbitrary link types dynamically — no hardcoded link type list.
