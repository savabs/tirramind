🔬 Ghost Pattern Detection: Technical Roadmap & Research Foundation

Purpose: Deep technical plan for implementing cross-domain anomaly detection for MP-1 (Atlantic energy supply chain)
Research Scope: Pure mathematics, arXiv (2024-2026), production GitHub repos
Target: Joint trajectory anomalies invisible to single-source analysis
Created: 2026-06-08

🎯 Executive Summary

Ghost patterns are joint trajectory anomalies across entities and domains — signals that only emerge when you fuse heterogeneous data sources (COT positioning, AIS vessel movements, weather, port congestion, prices). The technical challenge is building a system that:

  1. Ingests multi-domain time series (COT, AIS, USDA, weather, prices)
  2. Resolves entities across disparate schemas (ship → commodity → future contract → producer)
  3. Detects changepoints in each domain independently
  4. Discovers causal chains across domains (Granger causality, PCMCI+)
  5. Matches temporal graph patterns against known alert templates
  6. Scores anomalies using heterogeneous GNN fusion

This document lays out the technical foundation — papers, repos, algorithms — for each component.

📚 Research Foundation: State-of-the-Art (2024-2026)

1. Multivariate Time Series Anomaly Detection

OWLEYE: Zero-Shot Cross-Domain Graph Anomaly Detection (ICLR 2026)

arXiv: 2601.19102
Key Innovation: Cross-domain feature alignment module + multi-domain pattern dictionary learning
Why It Matters: We need to detect anomalies in NEW commodity niches (MP-2, MP-3) without retraining from scratch. OWLEYE's zero-shot transfer is crucial for scaling across micro-playgrounds.

Algorithm Components:

  • SVD-based feature alignment across domains
  • Meta-pattern dictionary (stores normal behavior templates)
  • Truncated attention-based reconstruction for unseen graphs

CGSTA: Cross-Scale Graph Contrast with Stability-Aware Alignment (Feb 2026)

arXiv: 2602.20468
Key Innovation: Dynamic Layered Graph Construction (DLGC) — builds local/regional/global views of variable relations per sliding window
Why It Matters: Commodity chains have multi-scale structure (local = port congestion, regional = Baltic routes, global = OPEC policy). CGSTA's hierarchical contrast learns features at each scale.

Algorithm Components:

  • DLGC: 3-layer graph per time window (local, regional, global)
  • Contrastive Discrimination across Scales (CDS)
  • Stability-Aware Alignment (SAA) — EMA-anchored regularization to suppress noise

PMGC: Prospective Multi-Graph Cohesion (Sep 2025)

arXiv: 2509.17235
Key Innovation: Long-term static graph + short-term dynamic graphs with cohesion loss
Why It Matters: Some commodity relationships are stable (crude → gasoline refining), others fluctuate (shipping routes during storms). PMGC balances both.

2. Changepoint & Regime Detection

Bayesian Online Changepoint Detection (BOCPD) for Financial Time Series (ACM 2025)

Paper: ACM DL
Key Innovation: Real-time probabilistic changepoint detection with hazard-rate parameter λ
Why It Matters: COT positioning extremes (z-score > 2σ) need automated regime labeling (Long Build-Up, Short Covering). BOCPD identifies structural breaks aligned with macro events.

Optimal Configuration (from paper):

  • maxCPs method with λ = 100
  • Successfully detected COVID-19, monetary policy shifts, pandemic phases

PELT (Pruned Exact Linear Time) Algorithm (ACM 2025)

Paper: ACM DL
Key Innovation: Linear-complexity globally optimal changepoint detection via dynamic programming
Why It Matters: Need to detect supply disruptions (e.g., Suez Canal blockage) with exact timing. PELT is fastest for large-scale commodity price series.

Best Cost Function: Normal cost function for financial/commodity data

Topological Data Analysis for Changepoint Detection (MDPI 2025)

Paper: MDPI
Key Innovation: Persistence homology features (L1, L2 norms) for long-term/short-term volatility indicators
Why It Matters: Detects "shape shifts" in multivariate commodity data. Identified Brexit, COVID-19, Russia-Ukraine war with 98% significance threshold.

3. Causal Discovery & Chain Detection

Tigramite: Causal Inference for Time Series (GitHub)

Repo: jakobrunge/tigramite
Key Algorithms:

  • PCMCI+ — Directed lagged + contemporaneous links
  • ParCorr — Partial correlation CI test
  • CMIknn — Conditional mutual information for nonlinear dependencies

Why It Matters: Discovers causal chains like CFTC net long → AIS cargo departures → port congestion → price spike. PCMCI+ handles both lagged (ship departs 7 days after COT report) and contemporaneous (price & volume spike together) links.

DoWhy: Causal Inference with Graphical Models (Microsoft Research)

Repo: py-why/dowhy
Key Feature: Root-cause analysis for supply chain shifts (week-over-week changes in received quantity)
Why It Matters: When MP-1 fires an alert ("Baltic crude shipments down 15%"), DoWhy can answer: "Why did received quantity change?" by tracing back through POs → vendor confirmations → logistics disruptions.

4. Heterogeneous Graph Neural Networks & Cross-Domain Fusion

CrossHGL: Text-Free Cross-Domain Heterogeneous Graph Learning (arXiv Mar 2026)

arXiv: 2603.27685
Key Innovation: Tri-Prompt system (feature, edge, structure prompts) + semantic-preserving graph transformation
Why It Matters: Commodity entities are heterogeneous (ships, contracts, ports, producers, weather zones). CrossHGL aligns them into a shared embedding space without external text labels.

MUG: Meta-path-aware Universal Heterogeneous Graph Pre-Training (Feb 2026)

arXiv: 2602.22645
Key Innovation: Input unification module — encodes heterogeneous types into unified representation via contextual structural information
Why It Matters: Meta-paths like Ship → Port → Producer → Future Contract → COT Report carry semantic meaning. MUG captures high-order relationships without LLM dependency.

5. Multi-View Contrastive Learning for Time Series

Multi-View Contrastive Learning for Domain Adaptation (arXiv Sep 2025)

arXiv: 2506.22393
Key Innovation: Integrates temporal, derivative, and frequency features via hierarchical fusion
Why It Matters: COT data has temporal patterns (weekly cycles), derivatives (positioning momentum), and frequency signatures (seasonal grain demand). Multi-view learning captures all three.

MoST: Mode-Specific Tensor Time Series (Feb 2026)

arXiv: 2602.23663
Key Innovation: Disentangled mode-specific representations via tensor slicing
Why It Matters: Ghost patterns live in the interaction between modes (time × entity × domain). MoST learns disentangled features that can be recombined to detect cross-mode anomalies.

6. Temporal Graph Pattern Matching

TemporalRI: Temporal Subgraph Isomorphism with Multiple Contacts

Paper: Applied Network Science
Key Innovation: Temporal flow filtering for subgraph matching
Why It Matters: Chain templates are temporal patterns: COT extreme(t) → AIS gap(t+3) → port loiter(t+5) → price(t+7). TemporalRI finds all instances of this template across historical data.

Raphtory: Temporal Graph Engine (Rust + Python)

Repo: Pometry/Raphtory
Key Feature: Temporal motif discovery, time-respecting paths
Why It Matters: Production-grade temporal graph engine. Can query: "Find all 3-node motifs where Ship → Port → Producer edges occurred within 7-day windows over 2022-2025."

🏗️ Technical Architecture: 7-Layer Stack Implementation

Layer 1: Surveillance (Multi-Domain Data Ingestion)

Data Sources for MP-1 (Atlantic Energy)

  • CFTC COT Reports: Weekly positioning for WTI, Brent, RBOB, Heating Oil
  • AIS Vessel Tracking: Tanker movements in Atlantic Basin (North Sea, Gulf, Caribbean)
  • Weather: Hurricane tracks, North Atlantic storm patterns (NOAA)
  • Port Congestion: Houston, Rotterdam, Singapore vessel density
  • Prices: ICE Brent, NYMEX WTI, futures term structure
  • News/Events: OPEC meetings, refinery outages, pipeline disruptions (optional for Phase 1)

Implementation Steps

  1. COT Ingestion: Use NDelventhal/cot_reports to fetch weekly reports → Mcamin/cot-analysis for regime detection → Store as cot_features.parquet
  2. AIS Ingestion: Stream from AISHub or MarineTraffic API → Filter tankers (MMSI vessel type = 80-89) → Run RadianceFleet gap detection → Store as ais_anomalies.parquet
  3. Price Data: Yahoo Finance or EOD Historical Data API → Daily OHLCV for WTI, Brent → Store as prices.parquet
  4. Entity Resolution: Map vessel_name → IMO → flag_state → cargo_type → futures_contract using Lloyd's List or Clarksons research data.
Technical Debt Note: Don't try to build perfect entity resolution in Phase 1. Use fuzzy string matching (RapidFuzz) + manual lookup tables for top 50 tankers. Automate later.

Layer 2: Feature Engineering (Signal Extraction)

Per-Domain Features

COT Features (from Mcamin/cot-analysis):

  • net_position_zscore_52w — Standard deviations from 52-week mean
  • net_position_percentile_52w — Percentile rank [0, 100]
  • regime_label — {Long Build-Up, Short Covering, Long Liquidation, Short Build-Up}
  • bias_score — Directional bias [0, 10] with confidence

AIS Features (from RadianceFleet + custom):

  • gap_duration_hours — AIS transmission gap length
  • loitering_flag — Binary: vessel stationary near load/discharge point
  • sts_transfer_flag — Ship-to-ship transfer detected
  • route_deviation_score — Distance from historical route cluster centroid
  • cargo_capacity_utilization — Estimated from draft (if available)

Price Features (custom):

  • return_volatility_20d — Rolling 20-day standard deviation
  • contango_magnitude — (Future 3M - Spot) / Spot
  • volume_spike_flag — Volume > 2σ above 60-day mean

Cross-Domain Feature Fusion

Use CrossHGL (arXiv 2603.27685) approach:

  1. SVD-based feature alignment: Project COT z-scores, AIS anomaly scores, price returns into shared 64-dim space
  2. Temporal binning: Align all features to weekly timestamps (COT publication Friday 3:30 PM ET)
  3. Lagged features: Create cot_zscore_lag7, ais_gap_lag3 to capture temporal dependencies
Math Note: For SVD alignment, stack all domain features into matrix X ∈ ℝ^(T×D) where T = time steps, D = total features. Compute U, Σ, V = SVD(X). Project each domain's features via X_domain @ V[:, :k] where k = 64 (aligned dims). This is dimension reduction + domain alignment in one step.

Layer 3: World Model (Temporal Graph Construction)

Graph Schema

Node Types:

  • Vessel — IMO, name, flag, capacity
  • Port — UN/LOCODE, lat/lon, congestion index
  • Producer — Country/company (e.g., Saudi Aramco, Shell)
  • FutureContract — Symbol (CLZ24), exchange, settlement date
  • COTReport — Date, commodity, net positioning by trader type
  • Event — OPEC meeting, hurricane landfall, refinery outage

Edge Types:

  • Vessel --[departed_from]--> Port (timestamp)
  • Vessel --[loaded_cargo]--> Producer (timestamp, volume)
  • FutureContract --[tracks]--> Producer (static)
  • COTReport --[positions_in]--> FutureContract (timestamp)
  • Event --[impacts]--> Port/Producer/FutureContract (timestamp, severity)

Implementation: DuckDB + Raphtory

  1. Store nodes/edges in DuckDB: Tables nodes, edges with columns (id, type, timestamp, properties)
  2. Load into Raphtory: Python bindings for temporal graph queries
  3. Sliding windows: For each week W, construct graph G_W containing all nodes/edges in [W-4weeks, W]
import raphtory as rp

g = rp.Graph()
g.add_vertex(timestamp=t1, id="V_IMO9999999", v_type="Vessel")
g.add_vertex(timestamp=t1, id="P_USHOU", v_type="Port")
g.add_edge(timestamp=t2, src="V_IMO9999999", dst="P_USHOU", layer="departed_from")

# Query: vessels that departed Houston in last 7 days
window = g.window(start=now-7days, end=now)
departures = window.edges(layer="departed_from", dst="P_USHOU")
Scale Note: MP-1 will have ~200 tankers, ~50 ports, ~20 contracts → ~10K nodes, ~100K edges over 2 years. This fits in memory. For MP-2/3/4, shard by commodity or use DuckDB's external storage.

Layer 4: Fusion (Heterogeneous GNN)

Architecture: MUG (Meta-path-aware Universal GNN)

Based on arXiv 2602.22645 (MUG paper):

  1. Input Unification: Each node type gets a learnable embedding + contextual structural info (degree, neighbor type distribution)
  2. Meta-path Attention: Define semantic paths:
    • Vessel → Port → Producer → FutureContract → COTReport (supply chain path)
    • COTReport → FutureContract → Producer (positioning-to-production path)
  3. Message Passing: For each meta-path, aggregate messages along the path using attention weights
  4. Readout: Node embeddings → global graph embedding via sum/mean pooling

PyTorch Implementation Sketch

import torch
import torch.nn as nn
from torch_geometric.nn import HeteroConv, GCNConv, Linear

class MetaPathGNN(nn.Module):
    def __init__(self, node_types, edge_types, hidden_dim=64, num_layers=3):
        super().__init__()
        # Input unification: learnable embeddings per node type
        self.node_embeddings = nn.ModuleDict({
            ntype: nn.Embedding(num_nodes[ntype], hidden_dim)
            for ntype in node_types
        })
        
        # Heterogeneous graph convolutions
        self.convs = nn.ModuleList()
        for _ in range(num_layers):
            conv_dict = {}
            for etype in edge_types:
                src, rel, dst = etype
                conv_dict[etype] = GCNConv(hidden_dim, hidden_dim)
            self.convs.append(HeteroConv(conv_dict, aggr='mean'))
        
        # Readout
        self.readout = Linear(hidden_dim, 1)  # Anomaly score
    
    def forward(self, x_dict, edge_index_dict):
        # Unify inputs
        for ntype in x_dict.keys():
            x_dict[ntype] = self.node_embeddings[ntype](x_dict[ntype])
        
        # Message passing
        for conv in self.convs:
            x_dict = conv(x_dict, edge_index_dict)
            x_dict = {k: v.relu() for k, v in x_dict.items()}
        
        # Global readout (sum over all nodes)
        graph_emb = torch.stack([x.mean(dim=0) for x in x_dict.values()]).mean(dim=0)
        score = self.readout(graph_emb)
        return score
Training Strategy: Use PMGC (arXiv 2509.17235) cohesion loss — balance long-term static graph (e.g., Brent always tracks North Sea production) with short-term dynamic graphs (e.g., hurricane disrupts Gulf Coast this week).

Layer 5: RL Policy (Chain Template Matching)

Objective

Given a library of chain templates (manually curated or mined from historical data), find all instances in the current temporal graph where the template fires.

Chain Template Example

Template: "Bullish Build-Up with Supply Disruption"

Pattern:
1. COTReport(t=T, net_zscore > 2.0, regime="Long Build-Up")
2. AIS gap(t=T+3d, vessel_type=Tanker, route=Gulf→Rotterdam)
3. Port congestion(t=T+5d, port=USHOU, density > 1.5σ)
4. Price spike(t=T+7d, return > 2σ)

Expected Outcome: Brent +5% over next 2 weeks
Historical Hit Rate: 68% (n=23 instances since 2020)

Implementation: TemporalRI + Raphtory

  1. Template as Query Graph: Encode template as a 4-node temporal graph with time constraints
  2. Subgraph Matching: Use TemporalRI algorithm to find all isomorphic matches in G_W (current window)
  3. Scoring: For each match, retrieve historical outcome distribution → compute P(price_up | pattern_match)
# Pseudo-code for template matching
from temporalri import TemporalSubgraphMatcher

template = TemporalGraph()
template.add_node("COT", constraint=lambda n: n['zscore'] > 2.0)
template.add_node("AIS", constraint=lambda n: n['gap_hours'] > 12)
template.add_edge("COT", "AIS", time_delta=(2, 5))  # 2-5 days later

matcher = TemporalSubgraphMatcher(template)
matches = matcher.find_all(G_current_window)

for match in matches:
    historical_outcomes = lookup_historical_outcomes(match.pattern_id)
    prob_up = len([o for o in historical_outcomes if o.price_change > 0]) / len(historical_outcomes)
    if prob_up > 0.6:
        fire_alert(match, confidence=prob_up)
Cold Start Problem: In Phase 1, we won't have historical outcomes for every template. Mitigation: Start with 3-5 high-conviction templates based on domain research (e.g., COT extremes → reversals is well-documented). Log all template matches in production → accumulate outcomes → update hit rates quarterly.

  2. Historical Backtesting: Run chain templates on 2020-2024 data → Calculate precision/recall for known events (COVID demand collapse, Suez blockage, Russia-Ukraine war)
  3. Adversarial Augmentation: Perturb input features (add Gaussian noise to COT z-scores) → Ensure GNN embeddings remain stable

🚧 Known Risks & Mitigation

Risk 1: Data Quality (AIS Gaps are Noise, Not Signal)

Problem: AIS transmission gaps might be due to technical issues (transponder malfunction) rather than intentional dark activity or supply disruption.

Mitigation:

  • Use RadianceFleet "velocity plausibility ratio" — If vessel reappears 500 miles away after 12-hour gap, it's likely spoofing/dark activity. If it reappears at the same location, it's likely technical.
  • Correlate AIS gaps with port congestion or weather events (gap during hurricane = probably sheltering, not dark fleet).
  • If AIS proves too noisy for MP-1, pivot to satellite-based vessel detection (Planet Labs or Capella Space SAR imagery) — more expensive but higher signal.

Risk 2: Cold Start (No Historical Outcomes for New Templates)

Problem: In Phase 4, we define chain templates but don't have historical outcome data for every pattern.

Mitigation:

  • Start with 3 templates backed by domain research (e.g., COT extremes → reversals is well-documented in academic lit).
  • For new templates, use lower confidence scores initially (prob = 0.5 instead of 0.7).
  • Log ALL template matches in production → Wait 2 weeks → Label outcome → Retrain outcome predictor quarterly.
  • After 6 months, we'll have ~50-100 labeled instances per template → Sufficient for ML.

Risk 3: Overfitting to Historical Regime Changes

Problem: 2020-2022 had unprecedented events (COVID, Russia-Ukraine). Models trained on this data might not generalize to normal market conditions.

Mitigation:

  • Train on 2015-2019 (pre-COVID) and test on 2023-2024 (post-COVID normalization).
  • Use adversarial validation: Check if features in test set are out-of-distribution vs. train set.
  • Prioritize robust features (z-scores, percentiles) over absolute values (raw COT net positions).

Risk 4: Entity Resolution Failure

Problem: If we can't reliably map vessel_name → IMO → cargo_type → futures_contract, the graph will have missing links.

Mitigation:

  • Phase 1: Manual lookup tables for top 50 tankers (covers ~70% of Atlantic crude volume).
  • Phase 2: Use Lloyd's List API or Clarksons data for automated entity resolution.
  • If resolution < 80% accuracy, downgrade graph-based features and rely more on time-series features (COT z-scores, price momentum).
