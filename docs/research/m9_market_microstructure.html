1. Order Flow Imbalance (OFI) — M9.1

1.1 Definition & Mathematical Foundation

OFI quantifies net buy/sell pressure by tracking changes in limit order book volume at the best bid and ask.

OFI(t) = Δvolume_bid(t) - Δvolume_ask(t) Where: - Δvolume_bid(t) = volume added to best bid minus volume removed from best bid - Δvolume_ask(t) = volume added to best ask minus volume removed from best ask

Source: Cont, Kukanov & Stoikov (2014). "The Price Impact of Order Book Events." Journal of Financial Econometrics

Key Insight: OFI is the strongest single predictor of short-term price changes. On BTC/ETH perpetual data (March 2026), OFI showed mean IC = 0.1505 with positive IC in 98% of 5-minute windows. Predictive power peaks at 1-5 seconds and decays by 60 seconds.

Source: Delphi Alpha HFT Secrets 1/5, March 2026, Binance Futures data

1.2 Decomposed OFI (Add/Cancel/Trade)

Modern HFT decomposes OFI into three event-driven components with distinct predictive power:

Component Predictive Rank Description
Add-OFI 1st Net volume added to book (new limit orders)
Cancel-OFI 2nd Net volume cancelled from book
Trade-OFI 3rd (weakest) Volume from executed trades

Source: Sitaru, Calinescu, Cucuringu (2023), ACM ICAIF

Cancel stream carries 30 percentage points of predictive power that trade-tape OFI leaves behind. Trade-tape only OFI caps at ~35% R² in forward-looking scenarios.

Source: HFT Advisory Substack, "Why Your Trade-Tape OFI Caps at 35% R-Squared"

1.3 Signal Horizon & Decay

Kolm, Turiel, Westray (2023) in Mathematical Finance found OFI is informative over approximately two average price changes. In liquid equities, this translates to 10-30 seconds in clock time (regime-dependent).

1.4 Implementation Strategy

For N1+N4: We lack tick-level orderbook data for commodity futures. Implementation options:

  • Option A: Trade-tape OFI from publicly available trades (weaker but available)
  • Option B: Signed volume classification from price changes (BVC-style, see VPIN)
  • Option C: Defer to L3 when tick data becomes available

Decision: Start with Option B (signed volume via price changes), matches VPIN methodology below. Upgrade to Option A when trade data available.

2. VPIN (Volume-Synchronized Probability of Informed Trading) — M9.2

2.1 Definition & Mathematical Foundation

VPIN measures order flow toxicity — the imbalance between informed traders and market makers. Unlike time-based metrics, VPIN uses a volume clock.

VPIN = (1/n) × Σ|V_buy_i - V_sell_i| / V_bucket Where: - n = number of rolling buckets (typically 50) - V_bucket = fixed volume per bucket (e.g., 100,000 shares) - V_buy_i, V_sell_i = buy/sell volume in bucket i (estimated via BVC)

Source: Easley, López de Prado, O'Hara (2012). "Flow Toxicity and Liquidity in a High-Frequency World." Review of Financial Studies

2.2 Bulk Volume Classification (BVC)

BVC classifies volume as buy or sell using the Normal CDF of price changes within a bucket:

V_buy = V_total × Φ((P_close - P_open) / σ_bucket) V_sell = V_total - V_buy Where: - Φ = standard normal CDF - σ_bucket = volatility estimate for the bucket

Source: Easley, López de Prado, O'Hara (2012)

2.3 Volume Bucketing Algorithm

  1. Set target bucket volume (e.g., 100,000 contracts for liquid futures)
  2. Accumulate trades until bucket volume reached
  3. Record bucket: (open, close, high, low, total_volume, timestamp_end)
  4. Classify bucket volume via BVC
  5. Compute VPIN over rolling window of n buckets (n=50 standard)
Calibration Parameters:
  • Bucket size: Adjust per instrument. Major FX pairs: ~1M units. Liquid equity futures: 50-100k contracts.
  • Rolling window: n=50 buckets (original paper). Shorter (20-30) = more responsive but noisier. Longer (100+) = smoother but lags.
  • Per-asset calibration: Store optimal bucket_volume in metadata DB, default to median daily volume / 200.

3. Hawkes Process for OFI Forecasting — M9.3

3.1 Mathematical Foundation

Hawkes processes model order flow as a self-exciting point process, capturing lagged cross-dependence between bid and offer events.

λ_buy(t) = μ_buy + Σ φ_buy,buy(t - t_i^buy) + Σ φ_buy,sell(t - t_j^sell) λ_sell(t) = μ_sell + Σ φ_sell,sell(t - t_j^sell) + Σ φ_sell,buy(t - t_i^buy) Where: - λ(t) = intensity (arrival rate) at time t - μ = baseline intensity - φ(τ) = kernel function (decay of past events)

Source: Nittur Anantha & Jain (2024). "Forecasting High Frequency Order Flow Imbalance using Hawkes Processes." arXiv:2408.03594, Computational Economics 67:279-312 (2026)

3.2 Sum of Exponentials Kernel (Best Performer)

The paper found Sum of Exponentials kernel gives best OFI forecast among all competing models on NSE tick data:

φ(τ) = Σ α_k × β_k × exp(-β_k × τ) Where: - α_k = amplitude of k-th exponential - β_k = decay rate of k-th exponential - Typical: k=2 (two exponentials capture fast + slow excitation)

3.3 Forecasting Framework

The paper develops method to forecast near-term distribution of OFI:

E[OFI(T+h, h) | F_T] = E[V_buy(T, T+h) - V_sell(T, T+h) | F_T] Computed via conditional intensity integrals of fitted Hawkes process.

3.4 Implementation Strategy

For N1+N4: Hawkes processes require high-frequency event data (orderbook events or trades). Implementation phases:

  • Phase 1 (Current): Skip Hawkes. Use simple OFI + VPIN from available data.
  • Phase 2 (When tick data available): Fit bivariate Hawkes (buy/sell) with Sum-of-Exp kernel.
  • Phase 3 (Advanced): Multi-level Hawkes (add/cancel/trade decomposition) per Sitaru et al.

Library: tick Python library for Hawkes process fitting (supports Sum-of-Exp kernel). Not differentiable — use as feature generator, not in backprop path.

4. Bid-Ask Spread Estimation — M9.4

4.1 Corwin-Schultz Estimator (Primary)

Estimates bid-ask spread from daily high/low prices only — no tick data required.

Key Insight: High (low) prices are almost always buy (sell) trades. - High-low ratio reflects both variance and spread - Variance scales with √time, spread does NOT - Compare 1-day vs 2-day high-low ratios to separate components β = [ln(H_t / L_t)]² γ = [ln(H_{t,t+1} / L_{t,t+1})]² α = (√(2β) - √β) / (3 - 2√2) - √(γ / (3 - 2√2)) Spread = 2(e^α - 1) / (1 + e^α)

Source: Corwin & Schultz (2012). "A Simple Way to Estimate Bid-Ask Spreads from Daily High and Low Prices." Journal of Finance 67:719-760

4.2 Censoring & Averaging

Three variants used in practice:

Variant Method Use Case
CSM (Censored) Average all, then max(result, 0) General
CSD (Daily censored) max(S_t, 0) then average Recommended for US equities, futures
CSP (Positive only) Average only S_t ≥ 0 FX spot rates

Source: Federal Reserve FEDS Working Paper 2019-051, Karnaukh et al. (2015)

For N1+N4: Use CSD variant (daily censoring before averaging). This is standard for commodity futures. Expect ~3.1% of estimates to be negative (set to zero per convention).

4.3 Roll Estimator (Secondary)

Uses negative serial covariance from bid-ask bounce:

Spread_Roll = 2√(-Cov(r_t, r_{t-1})) If Cov < 0, else set to 0.

Source: Roll (1984). "A Simple Implicit Measure of the Effective Bid-Ask Spread in an Efficient Market." Journal of Finance 39:1127-1139

Note: Roll estimator less reliable in crypto/futures markets where bid-ask bounce is weaker. Use Corwin-Schultz as primary.

5. Kyle's Lambda (Price Impact) — M9.5

5.1 Definition & Mathematical Foundation

Kyle's λ measures price impact — how much price moves per unit of signed order flow.

ΔP_t = α + λ × Q_t + ε_t Where: - ΔP_t = price change (log return or price level) - Q_t = signed order flow (net buy volume - net sell volume) - λ = Kyle's lambda (coefficient of interest)

Source: Kyle (1985). "Continuous Auctions and Insider Trading." Econometrica 53:1315-1335

5.2 Equilibrium Formula

In Kyle's model equilibrium:

λ = σ_v / (2σ_u) Where: - σ_v = standard deviation of asset's true value (uncertainty) - σ_u = standard deviation of noise trading Higher λ → less liquid market (each trade moves price more) Lower λ → more liquid market (order flow has minimal impact)

5.3 Empirical Estimation (Rolling Window)

Standard practice for time-varying λ estimation:

  1. Rolling window: Use past 720 hours (30 days) of data
  2. Aggregate to hourly: Compute hourly ΔP and Q
  3. OLS regression: ΔP_τ = λ_T × Q_τ + ε_τ for τ ∈ [T-720, T]
  4. Extract λ̂_T: This is the price impact for day T
  5. Roll forward: Repeat daily to get time series {λ̂_t}

Source: Polymarket study (arXiv:2603.03136v2), Federal Reserve methodology

Interpretation:
  • For BTC prediction markets: λ ~ 0.4 (illiquid early stage) → 0.01 (mature liquid market)
  • At p=0.5, λ=0.01: $1M net buy moves price by only 0.25%
  • λ is inversely proportional to market depth and trading volume

5.4 HAC Standard Errors

Use Newey-West HAC standard errors for robust inference (autocorrelation in residuals common in HFT data).

Source: drelick/kyle-1985-digital-variant (GitHub), crypto implementation

Lambda_regime 3 One-hot: [liquid, normal, illiquid]
Hawkes_OFI_forecast 1 E[OFI(t+5s) | F_t] (Phase 2+)

6.2 Cross-Entity Features (L3 Future)

When multiple instruments in same asset class:

  • OFI correlation: Rolling correlation of OFI(i, t) vs OFI(j, t) → edge weights
  • Hawkes cross-excitation: φ_{i→j} kernel amplitude → directed edge weights
  • Lambda dispersion: Std dev of λ across related instruments → market-wide liquidity stress indicator

6.3 Differentiability Requirements

Critical Invariant: Features must be computed in PyTorch for gradient flow. Non-differentiable operations (e.g., Hawkes fitting, rolling OLS) are precomputed offline and stored as static features. Only feature aggregation and normalization happen in forward pass.
