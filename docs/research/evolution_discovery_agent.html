Research: Evolution Discovery Agent — TirraMind Core Runtime

Status: Active — canonical research for the agent engine that makes TirraMind succeed.
Date: 2026-06-09
Commercial frame: [[0003-agents-as-sku]] · Playground proof: [[finance_playground_proof_ladder]]

One sentence: Build an evolution discovery agent — a low-level, hardware-aware runtime that discovers structure in multi-domain data through latent world models + RL, closes the loop on real outcomes, and is not prompt engineering with extra steps.

1. What “uncensored” means here (technical, not hype)

Not: unfiltered LLM text / ignoring safety on outputs to humans.

Yes — exploration without artificial ceilings:

  • Sensor access: agent may query any wired tool in the playground (no “we only look at prices”)
  • Hypothesis space: may propose new chain templates, features, arms — subject to eval gate, not editorial veto
  • Failure tolerance: dead ends logged in memory; bandit/RL down-weights, does not hide
  • No narrative layer: learning signal = numeric outcomes (IC, detection rate, calibration), not “sounds smart”

Guardrails stay hard-coded: schema invariants, leakage checks, deterministic pipeline, no live brokerage without explicit act module.

2. Agent identity: Evolution Discovery Loop

OBSERVE   → pipeline DAG + tools (deterministic L0/L1/L2)
ENCODE    → graph + ℰ (HetTGN / SSL / JEPA-style latent)
IMAGINE   → world model rollouts (latent next-state prediction)
PROPOSE   → detectors, features, goals, policies (evolution / bandit / RL)
ACT       → fetch, train job, export, alert log (no human prompt per step)
SCORE     → playground metrics (IC, chain resolution, calibration)
EVOLVE    → update weights, archive, thresholds, bandit, population

Anti-pattern: LLM writes a better prompt → call that “learning.” Real learning = parameters, policies, or population that change behavior on the same held-out eval.

3b. Existing autonomy loop (important distinction)

agent/core/autonomous.py implements reflect → bandit arm → LLM goal → orchestrator → reward. That is meta-level exploration (what task to run). The evolution discovery agent needs a lower layer:

  • Meta loop (existing): which research arm / tool chain to try
  • Discovery loop (new focus): which representations, detectors, and policies survive held-out playground eval

Keep both; do not confuse LLM goal generation with world-model learning.

5.1 JEPA on finance (concrete, not generic)

Objective: Given entity observation sequence o_{t-k:t}, predict next latent ẑ_{t+1} in ℰ; align to encoder output z_{t+1} (Barlow Twins / cosine).

Not: predict next price tick (too noisy). Yes: predict next fused world-state embedding for instrument / country / vessel entity.

Playground proof: frozen JEPA encoder → Stage-2 ranker beats momentum on [[finance_playground_proof_ladder]] P4.

5.2 Evolution discovery (concrete)

Population: detector configs (chain templates, z thresholds, lag windows) + small ranker heads.

Fitness: held-out playground score only (IC, chain calibration, false-positive rate).

Selection: top-k survive; mutate thresholds/lags; no LLM rewrite of math.

Gen-0: current 3 YAML templates in templates/ghost_chains/mp1/.

6. What “fast” means (ordered)

  1. Algorithmic: O(n) windowing, graph caching, bisect obs prefetch (Phase 40 wins — keep)
  2. Systems: batch graph samples, pinned memory, torch.compile on encoder forward
  3. Store: mmap SQLite / read replicas for training workers
  4. Custom kernels: only if profiling shows >30% time in one op (graph neighbor gather, CDE solver step)

Carmack rule: measure first; custom CUDA is a badge of honor, not day-one architecture.

9. Anti-patterns (reject)

  • Calling prompt changes “evolution”
  • Stacking architectures before P4 verdict
  • Custom CUDA before profiler
  • LLM-as-oracle for numeric edge
  • Skipping deterministic observe layer (breaks reproducibility)
