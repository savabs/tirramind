Research: Full-Quant Base Model

Date: 2026-06-03  |  Status: Active research (strategy)  |  Owner: Canonical strategy for M14+M15 + HetTGN training doctrine

Thesis (founder direction): Predictiveness should come from a general quant-conditioned base (broad markets, full Layer-2 math on the graph, rich ℰ), then niche finetuning (N1+N4 commodities / geopolitics) — analogous to LLM pretrain on broad corpus → SFT/LoRA on a domain. The base must be “sexy strong” (auditable OOS edge on multiple readouts), not a single-ticker hack.

2. Why “full quant” should help predictiveness

2.1 Information orthogonal to price alone

  • Options chain encodes risk-neutral distribution (IV, skew, term) — forward-looking vs realized vol in daily bars (M5/M6).
  • Rates curve (M15.3) conditions discounting and cross-asset fair value — links sovereign nodes to instruments.
  • Positioning + micro (CFTC, M9) — who is crowded; options can confirm or contradict positioning extremes.
  • Copula / TE (M10, M14.2) — tail dependence and directional information flow as edge features, not hand rules.

2.2 “Confirming predictiveness” without fooling ourselves

Options are valuable as secondary validators and extra heads, not as post-hoc narrative:

  • Feature path: surface features at T → predict Δrealized vol or return at T+h.
  • Consistency path: when GNN surprise ↑, does skew/ATM IV ↑ within h days? (lead-lag audit)
  • Disagreement path: model bullish vol, surface flat → flag for investigation (early signal or model wrong).

All claims require walk-forward IC / Brier / calibration — same discipline as Phase 41b.

2.3 Literature anchors (source-backed theory)

  • SVI / no-arb surfaces: Gatheral & Jacquier (2014) — arbitrage-free parameterization; repo implements M5.1–M5.4 in agent/quant/volatility.py.
  • Rough vol: Bayer, Friz, Gatheral — Hurst H < ½; M6.5–M6.6 in agent/quant/rough.py.
  • Microstructure: Roll (1984) spread; Easley et al. VPIN; Kyle λ — M9 in agent/quant/microstructure.py.
  • Constrained portfolio: Rockafellar & Uryasev (2000) CVaR — planned M7.2 (not yet wired).
  • Transfer entropy: Schreiber (2000) — planned M10.1 for directed edges.
  • GNN + limited labels: Contrastive pretrain → fine-tune discussed in [[architecture_stress_test]] (Stanford CS224W course notes cited there) — aligns with base→finetune.

6.3 “Derivatives” — which ones matter for predictiveness

  • Futures: Already your backbone — physical commodities, equity index risk, rates proxies (ZN, ZB ETFs).
  • Listed options (equity + index + commodity): Highest marginal value for full quant — implied distribution, skew, term structure ([[full_quant_base_model]] §2).
  • Futures ≠ options: You can have CL futures daily bars without CL option IV — M15 must add the options leg explicitly.
  • ETFs: Treat as cash proxies (SPY, sector ETFs) — you already have 36 equity/sector ETFs with daily data.
  • Swaps/CDS: Skip until T2; not needed to beat commodity-only IC.

6.5 Recommended M15 expansion order (base model)

  1. Rates: Backfill US curve (existing sovereign_debt + FRED) — free, enables BSM r(T).
  2. Options EOD: SPY + SPX (or QQQ) chains — general vol base for N2.
  3. Commodity options: CL, GC, NG (CME) — aligns with N1 finetune.
  4. Equity index options: ES options — links macro equity risk to futures.
  5. Dividends: Names you price with M2 (ETFs + large underlyings).
  6. Tick (M15.2): Only if policy allows — Hawkes/VPIN v2.

You do NOT need every derivative product for a strong base — you need liquid instruments with linked underlying + options + rates, ingested point-in-time.

9. Risks & mitigations

  • Feature explosion without data → mask bits + gate scripts per block (extend Gate B/C).
  • Paid data vs cost doctrine → treat M15 as infra budget; document ROI vs Kaggle GPU time.
  • Look-ahead in chains → observed_at = quote time; walk-forward only.
  • Skipping base → finetune → commodity-only ℰ may not transfer; still run Phase A for baseline.
  • Hand-coded rules → options “confirmation” must be learned weights or audited lead-lag, not if-statements.
