🌙 M1 Spec: Continuous-Time Heterogeneous World Model

TirraMind Moonshot — Neural SDE on a Heterogeneous Event Graph — 2026-05-27

MOONSHOT RES effort PhD-novel synthesis

1. Problem Statement

TirraMind currently processes the world in discrete snapshots: events are bucketed into fixed windows, processed by HetTGN, and embeddings used for return prediction. Three structural limits:

Limitation 1 — Discretization Error

AIS pings arrive every 5 min; PMI arrives monthly. Both are forced into the same 86400-second window. Two events at t=0 and t=86399 are treated as simultaneous. The model cannot learn from event timing.

Limitation 2 — Deterministic Point Embeddings

HetTGN produces point embeddings with no uncertainty. When a ship goes dark, there is no mechanism to represent growing positional uncertainty — the last known embedding is used unchanged forever.

Limitation 3 — Phase 9 World Model Sees Only Aggregates

The Phase 9 Bayesian world model (docs/specs/world_model_spec.md) operates on daily/weekly EngineeredFeatures. It cannot represent entity-level dynamics at sub-daily resolution.

M1 solves all three by replacing the discretized GNN pass with a Neural SDE that evolves continuously, conditioned on the heterogeneous graph, with explicit uncertainty via the diffusion term.

3. Mathematical Formulation

3.1 The Core Equation

dX_i(t) = f_theta( X_i(t), {X_j(t)}_{j in N(i)}, Z(t) ) dZ(t) [CDE drift] + g_phi( X_i(t) ) dW_i(t) [SDE diffusion] X_i(t) in R^d -- latent state of entity i at continuous time t N(i) -- heterogeneous neighbours of entity i in graph G(t) Z(t) -- control path: built from event stream via Hawkes + signatures f_theta -- drift network: HGT attention + Mamba SSM g_phi -- diffusion network: diagonal MLP (start simple) W_i(t) -- independent Brownian motion per entity d = 64 -- matches existing TrainerConfig hidden_dim

3.2 The Control Path Z(t): Three-Stage Construction

Z(t) is the driver of the CDE. Built from the event stream in three stages:

Stage A — Temporal Skeleton via Neural Hawkes

The LSTM decay state h_hawkes(t_k) from neural_hawkes.py encodes how excited the system is at each event time. This replaces naive linear interpolation with a learned temporal process.

lambda*_k(t) = softplus( W_out * h(t) + b_out )_k h(t) = h_n * exp( -softplus(w_decay) * (t - t_n) ) [decay between events] h_n = LSTM( concat(TypeEmb[k_n], delta_t_n), h_{n-1} ) h_hawkes(t_k) becomes a knot in Z(t).

Stage B — Path Shape via Log-Signatures

Project each event message to R^4, then compute the depth-3 log-signature of the projected path. Log-signatures encode area, curvature, and third-order path texture — invariant to time reparametrization, invisible to RNNs.

LogSig depth-3 for d=4 input: 4 + 16 + 64 = 84 features per knot (iisignature C extension; fallback to depth-2 = 20 features if unavailable) Signatures capture: did the path loop? oscillate? monotone? asymmetric? Two identical arrival/departure times but different intermediate paths produce different signatures -- this is the information RNNs miss.

Stage C — Cubic Spline Interpolation (torchcde)

knot_k = cat( [h_hawkes(t_k), log_sig_k] ) shape: (d_hawkes + 84,) = (148,) Z(t) = CubicHermiteSpline( knots, times ) continuous, differentiable dZ/dt = Z'(t) available analytically from spline coefficients d_z = 148 control path dimension

3.3 The Drift Network f_theta

Step 1 Graph aggregation (HGT attention): m_i(t) = HGT_Attention( X_i(t), {X_j(t)}_{j in N(i)} ) --> R^d Step 2 Token construction: tok_i(t) = Linear( [X_i(t) || m_i(t) || dZ/dt] ) --> R^{d_mamba} Step 3 Mamba sequential drift (long-range memory): out = Mamba( [tok_i(t_0), ..., tok_i(t_k)] )[-1] --> R^{d_mamba} Step 4 Project to drift matrix: F = Linear(out) --> R^{d x d_z} dX_drift = F @ (Z(t+h) - Z(t)) [CDE increment]

3.4 The Diffusion Network g_phi

OptionFormParamsWhen
A — Diagonal (start)g_phi(X) = diag(softplus(MLP(X)))O(d)Phase E of curriculum. Independent noise per entity dim.
B — Low-rankg_phi(X) = L(X) in R^{d x r}, r<<dO(d*r)Correlated noise within entity. After A is stable.
C — Graph-conditionalg_phi(X, G) uses neighbour statesO(d^2)Crisis contagion modelling. Future extension only.

3.5 Euler-Maruyama Solver (Implementation)

X_{t+h} = X_t + F(X_t, G_t, Z) @ (Z(t+h) - Z(t)) [CDE drift] + diag(g_phi(X_t)) * sqrt(h) * eps_t [SDE noise: eps ~ N(0,I)] Step size h = 0.1 * median_inter_event_time (adaptive) Milstein correction (second implementation): adds 0.5 * g * (dg/dX) * (eps^2 - 1) * h reduces bias from O(h) to O(h^2)

Four specific novelty claims:

  1. Heterogeneous node types in a Neural SDE: All prior graph SDE work uses homogeneous GCN. HGT with type-specific multi-head attention inside the SDE drift function is genuinely new.
  2. Hawkes process as control path driver: Prior Neural CDEs interpolate observed values deterministically. In M1, the control path Z(t) timing is a learned probabilistic process driven by event excitation patterns.
  3. Path signatures as the control path feature map: Combining rough path theory (Lyons 1998) with Neural CDEs: signatures encode path shape; the CDE integrates against the shape-enriched path rather than raw values.
  4. Mamba as in-solver drift parameterizer: Mamba's selective state transitions give the drift function long-range event memory (O(n) cost) at each solver step, instead of truncated attention O(n^2).

5. Component Integration Map

All five components already exist. M1 is the synthesis layer that wires them:

Component 1 — Neural Hawkes — agent/convergence/neural_hawkes.py

M1 role: Produces h_hawkes(t_k) at each event time — the temporal skeleton of Z(t). Encodes how excited the system is at each moment.

Current state: _predict() returns intensity predictions. The LSTM hidden state h(t) is computed internally but not exported to callers.

Delta: Add get_hidden_sequence(events) -> Tensor(n, d_hawkes) that exports h(t_k) for each event k without running the intensity head. ~15 lines.

Component 2 — Path Signatures — new agent/models/gnn/signature_path.py

M1 role: Encodes shape of the event path between Hawkes knots. Two ships with identical event times but different intermediate trajectories have different signatures.

Current state: Signatory/iisignature referenced in TS2Vec but no standalone path signature builder exists in the codebase.

Delta: New SignaturePathBuilder class (~100 lines): project messages to R^4, compute depth-3 log-signature via iisignature, return (n, 84) tensor. Manual depth-2 fallback (20 features) if iisignature not installed.

Component 3 — Neural CDE — agent/models/gnn/cde_encoder.py

M1 role: Integration engine. torchcde.cdeint(Z, f_theta, X_0, t_span) performs the CDE solve. Returns X(T) — the updated entity state.

Current state: CDEMemoryEncoder wraps torchcde with a self-contained CDEFunc that only sees X_i. No graph context, no Mamba.

Delta: New HeterogeneousCDEFunc(nn.Module) (~80 lines) that accepts (X_i, graph_message, Z_derivative) and calls Mamba drift inside the solver loop.

Component 4 — Mamba Encoder — agent/models/gnn/mamba_encoder.py

M1 role: Parameterizes drift matrix F at each solver step. Selective state allows the drift to ignore routine pings and amplify signal events across arbitrarily long histories.

Current state: MambaMemoryEncoder returns a scalar memory vector. No drift matrix output format exists.

Delta: Add get_drift_matrix(token_seq) -> Tensor(d, d_z) method (~25 lines). Reuses existing Mamba forward pass; changes only the output projection shape.

Component 5 — HetTGN + HGT — agent/models/gnn/het_tgn.py

M1 role: Graph-conditioned neighbourhood message m_i(t) = HGT(X_i, {X_j}). This is the G(t) term — which neighbours matter now, and how much.

Current state: AttentionCapturingHGTConv already exports attention weights. Can be called with arbitrary X(t) node features at any time t.

Delta: None for correctness. Performance optimization later: cache m_i between events; only recompute when a neighbour fires a new event.

New Component — Diffusion Head — agent/models/gnn/diffusion_head.py

M1 role: g_phi(X_i) = diag(softplus(MLP(X_i))). Per-dimension noise scale. During training: noise eps ~ N(0,I) scaled by g output and sqrt(dt). During inference: g output used as uncertainty estimate only; noise is zero for point prediction.

Delta: New file ~60 lines. Simple 2-layer MLP, softplus output, minimum floor 0.001.

6. Training Strategy

6.1 Multi-Task Loss

L_total = lambda_ret * L_return + lambda_evt * L_hawkes + lambda_kl * KL_term + lambda_obs * L_obs L_return = Huber( predict_return(X_i(T)), y_i ) [existing head] L_hawkes = CrossEntropy( lambda*_k(t_i), k_i ) [existing NHP] KL_term = 0.5 * sum( sigma^2 + mu^2 - log(sigma^2) - 1 ) [diagonal Gaussian KL] L_obs = MSE( predict_value(X_i(t)), obs_value ) [reconstruction] Weights: lambda_ret=1.0, lambda_evt=0.3, lambda_kl=0->0.01 (anneal), lambda_obs=0.5

6.2 Gradient Method: Adjoint SDE

MethodMemory costBiasVerdict
Backprop through solver (BPTT)O(n * d^2)NoneOnly for <50 events per entity per window
Adjoint method — Li et al. 2020O(d)Float32 rounding onlyUse this. torchdiffeq already a dependency.
Score function / ELBO — Kidger 2021O(d)High varianceAdd later when diffusion term dominates

Adjoint method stores only the final state and re-integrates backwards to compute gradients. O(d) memory vs O(n*d) for BPTT. The SDE noise is added as a Euler-Maruyama correction on top of the ODE adjoint — valid approximation when sigma << mu (early training).

6.3 Five-Phase Training Curriculum (Mandatory for Stability)

Warning: Training all components simultaneously from scratch will diverge. The CDE solver gradient is extremely sensitive to drift function initialisation. Starting from the existing trained HetTGN checkpoint is mandatory.

8. Risks and Mitigations

Risk 1 — CDE Solver Instability (HIGH)

Drift function gradients explode when poorly initialised. The adjoint re-integration amplifies this.

Mitigations: (a) Mandatory Phase A start from pre-trained HetTGN checkpoint. (b) Clip drift matrix column norms to 1.0. (c) Five-phase curriculum — never train all components simultaneously. (d) Monitor solver step rejection rate; halt if >30%.

Risk 2 — HGT Call at Every Solver Step is Slow (HIGH for wall-clock)

With 100 Euler steps per window and 5ms per HGT call: 500ms per entity per window → 10x slowdown.

Mitigations: (a) Cache m_i(t) between events — only recompute when a neighbour fires a new event. (b) During solver sub-steps between event times: use cached m_i. (c) Pre-aggregate top-K neighbours once per window with frozen embeddings for sub-step interpolation.

Risk 3 — KL Collapse in Diffusion Term (MEDIUM)

g_phi collapses to zero → SDE degenerates to CDE, KL provides no gradient signal.

Mitigations: (a) Anneal lambda_kl 0 to 0.01 over 10 epochs (beta-VAE schedule). (b) Minimum noise floor: softplus(MLP) + 0.001. (c) Alert if mean KL < 0.01 after Phase E epoch 5.

Risk 4 — Signature Dimension Explosion (MEDIUM)

Depth-3 signatures for d=8 projection: 8 + 64 + 512 = 584 features. Cubic growth with depth.

Mitigations: (a) Project messages to R^4 before signature (4+16+64=84 features). (b) Use log-signature (much smaller than full). (c) iisignature C extension is ~100x faster than pure Python. (d) Fallback to depth-2 (20 features) if iisignature unavailable.

Risk 5 — Memory Footprint per Entity (LOW)

Per entity: X_i (64 floats) + Mamba state (64/layer) + Hawkes h (64) = ~192 floats. 5000 entities: 192 * 5000 * 4 bytes = 3.7 MB. Acceptable on T4 (15 GB VRAM).

No mitigation needed at current scale. Quantise Hawkes state to float16 if entities exceed 50k.

Open Research Questions

  • Q1: Does Hawkes-driven Z(t) give strictly better gradients than cubic spline interpolation of raw messages? (Ablation: Phase D with vs without Hawkes Z construction.)
  • Q2: Does the path signature add information beyond the Hawkes state alone? (Ablation: drop log_sig from Z knots, compare validation IC.)
  • Q3: What is the optimal d_mamba for the drift vs. for memory? Both currently use 64. The drift might benefit from d_mamba=128 (more expressive matrix F).
  • Q4: Should g_phi be entity-type-specific? Vessels may warrant higher noise scale than macro indicators (PMI, credit spreads).
  • Q5: Can M1 entity distributions entirely replace the Kalman filter in Phase 9? M1 is non-linear and non-Gaussian; Phase 9 Kalman is linear-Gaussian. These are complementary, not redundant — but the boundary is an empirical question.
