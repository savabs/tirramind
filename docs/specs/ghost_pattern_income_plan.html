SKU: We sell detected ghost patterns — joint cross-domain chain anomalies that no single data vendor or z-score dashboard can see. Not API fetch + chart + newsletter. Not “our AI flagged.” The customer pays for asymmetric chain intelligence in a market so narrow that generalists do not compete.

1. Why micro-niches (not broad N1+N4)

N1+N4 fused ([[n1_n4_playground_spec]]) is the playground. Income ships in micro-playgrounds (MP) — instrument clusters where:

  • The ghost chain is named and auditable (3+ sensor types, explicit graph path).
  • The buyer self-identifies (“I trade cocoa” / “I hedge NG”) — not “I read macro.”
  • Competition is COTBase-style single-source tools, not Jane Street.
  • We can populate L0 sensors for that chain only before the full 89-instrument graph is perfect.

2. What counts as intelligence (acceptance criteria)

Every paid output must pass all four:

#GateFail example
G1Chain — cites ≥2 domains in one alert (e.g. physical + positioning, not CFTC alone)“WTI CFTC +2σ” with no supply/flow context
G2Graph path — internal template ID links entities (auditable in signal JSON)Hand-wavy “cross-domain” prose
G3Source — every node in chain has public URL + timestampBlack-box model score
G4Outcome log — alert archived before resolution; scorecard updatedRetrofitted “calls”

ML depth ramps: Phase A explicit chain templates + anomaly thresholds → Phase B embedding trajectory (TDC-AE) → Phase C GNN readout when two-stage passes gate. Income can start at Phase A if G1–G4 hold.

6. Technical build (intelligence, not wrapper)

6.1 Phase A — Chain template engine (ship income)

New leaf: agent/quant/ghost_chains.py + scripts/ghost_pattern_scan.py

  • YAML chain templates per MP (entity types, obs types, min z-scores, max lag).
  • Graph walk: match active anomalies on path within rolling window.
  • Score = product of normalized node anomalies × path completeness.
  • Output → ghost archive JSON + brief markdown section.

~200 LOC core. Uses existing pipeline.db — no new external APIs required for MVP.

6.2 Phase B — Trajectory detector (parallel R&D)

  • embedding_snapshots table per [[machine_intelligence_architecture]]
  • TDC-AE anomaly on pooled ℰ trajectory per MP subgraph
  • Alerts merge: template OR trajectory (both must pass G1–G4)

6.3 Phase C — GNN readout (when ready)

  • Two-stage architecture ([[gnn_two_stage_spec]]) — encoder supplies features to chain scorer
  • GNN improves ranking within MP; does not replace chain audibility
